## Locality

Memory moves in **cache lines** (64 bytes on current x86-64 CPUs). Code that uses neighbouring data (**spatial locality**) or reuses data soon (**temporal locality**) runs from fast caches instead of DRAM. C arrays are row-major, so walking a row uses every byte of each line it fetches.

## The roofline model

The roofline model (Williams, Waterman and Patterson, Berkeley tech report EECS-2008-134) bounds attainable performance:

```text
attainable FLOP/s = min(peak FLOP/s, arithmetic intensity × peak bandwidth)
```

**Arithmetic intensity** is FLOPs per byte moved. Kernels left of the **ridge point** (peak FLOP/s ÷ bandwidth) are memory-bound; kernels to its right are compute-bound.

```mermaid
flowchart LR
  L["low intensity: memory-bound"] --> R(("ridge point")) --> C["high intensity: compute-bound"]
```

## Why blocking works

Naive N×N matmul does 2N³ FLOPs but, for large N, reloads the same values from memory many times. **Blocking** computes on tiles small enough to stay in cache, raising arithmetic intensity without changing the FLOP count.
