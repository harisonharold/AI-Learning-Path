# Claude Code Master Implementation Prompt: "Systems Atlas"

You are building a real, working web application in this repository: a personal learning, research and open-source-contribution platform for one learner (Harison) who has a 2-year Computer Programming diploma and wants to become credible in distributed systems, AI infrastructure, GPU/CUDA, HPC, distributed databases, low-latency networking, systems programming, ML systems, inference optimization and Kubernetes within 16-24 weeks. The app must move the learner forward only on **demonstrated competence** and turn the work into **verifiable public evidence** (tests, benchmarks, merged PRs, reports). It must say plainly that 4-6 months does not make anyone an expert and that it cannot promise interviews, offers or salaries.

This prompt is self-contained. Do not assume any other document exists.

---

## 0. Non-negotiable rules

1. **Inspect first.** Before changing anything, inspect the repository (files, existing code, git history) and summarise what exists.
2. **Plan, then stop.** Write `PLAN.md` and `THREAT_MODEL.md` (contents in §9). Then **stop and wait for my explicit approval**. Do not write application code before I approve.
3. **Build in phases** (§10). After each phase the app must start with one command and everything built so far must work. Run lint, typecheck and all tests before you say a phase is finished.
4. **Never claim an untested feature works.** A feature counts as done only when its acceptance tests pass. Keep `TASKS.md` (backlog with status) and `PROGRESS.md` (what was done, what was tested, what failed, what is not done) up to date after every work session.
5. **Mock data only where a live integration is unavailable**, and always labelled: records carry `is_mock=true`, the UI shows a persistent "SAMPLE DATA" banner, and mock data never appears in analytics, the portfolio or reports.
6. **Integrations only when their credentials exist.** Without GitHub/AI credentials, show a clear "not configured" state; never crash and never fake a connection.
7. **No automatic outward actions.** The app must never open pull requests, post comments, contact maintainers, or post to LinkedIn or anywhere else. Request read-only GitHub permissions so this is enforced by capability. Generate text (PR descriptions, resume bullets, posts) only for the user to copy.
8. **API keys and secrets stay server-side only.** Never put them in client bundles, logs, URLs or API responses. Store user-provided AI keys encrypted (AES-256-GCM, key from env), write-only. Add a CI check that fails the build if secret patterns appear in `.next/static`.
9. **No invented facts.** Every external fact shown (paper, repo stat, price, job requirement) must come from a stored source record with URL and `verified_at`. Seed sources below were verified on 2026-11-16; build a verification job that re-checks them, and show a "stale" warning after 30 days. Never let an LLM create a citation.
10. **Browser JavaScript cannot run CUDA or control GPUs.** GPU work runs through the local runner CLI (§6.4) on the learner's machine or a rented GPU box.
11. **One developer must be able to maintain it.** Modular monolith, at most ~7 containers, no microservice sprawl, no paid dependency required.
12. **Ask before** adding any dependency not listed here, changing the stack, or making a decision this prompt leaves open; record decisions in `PLAN.md` under "Decisions".

## 1. Stack (check the current stable version of each when installing; pin in lockfiles)

- **Web:** Next.js (App Router; v16.x was current on 2026-11-16) + React + TypeScript `strict` + Tailwind CSS v4 + shadcn/ui on Radix Primitives (accessible components).
- **Charts:** Apache ECharts (one library for all charts). **Diagrams:** React Flow (xyflow) for interactive diagrams, Mermaid for static ones. **Content:** MDX + Shiki. **Editor:** Monaco. **In-browser Python:** Pyodide.
- **Auth:** Better Auth with GitHub social sign-in and its MySQL adapter. (Auth.js's own README now recommends Better Auth for new projects.) Roles: `learner`, `reviewer`, `admin`; public routes for the portfolio only.
- **GitHub data:** a **GitHub App** with read-only permissions (metadata, contents, issues, pull requests) using user-to-server tokens. GitHub's docs say GitHub Apps are preferred over OAuth apps. Use only the official REST API, ETags and rate-limit headers. Search is limited to 30 requests/min when authenticated.
- **Database:** MySQL 8.4 LTS, InnoDB, utf8mb4. ORM and migrations: **Drizzle ORM + drizzle-kit**. The TypeScript schema is the single source of truth. The Python service never writes the main DB (single-writer rule). Use MySQL FULLTEXT for paper search; MySQL VECTOR columns can't be keys or indexed, so don't build semantic search in v1.
- **Compute service:** Python 3.12+, FastAPI, Pydantic, managed with uv, linted with ruff, type-checked with pyright, tested with pytest.
- **Queue/cache:** Redis 7 + **BullMQ** (Node producers and a Node worker; a Python worker using the `bullmq` PyPI package). Phase 0 includes a spike to prove the Python worker round-trip. If it fails, use RQ inside the Python service instead and record the decision.
- **Validation:** Zod (TS) and Pydantic (Py). Shared JSON Schemas live in `packages/contracts` and are tested on both sides.
- **Tests:** Vitest, Playwright, @axe-core/playwright, Testcontainers (MySQL/Redis), pytest. **Lint/type:** ESLint (+ an import-boundary rule, e.g. eslint-plugin-boundaries), `tsc --noEmit`, ruff, pyright.
- **Observability:** OpenTelemetry (JS + Python) to Jaeger locally; structured JSON logs; `/healthz` on every service; optional Sentry free tier.
- **Dev/CI:** pnpm workspace, Docker Compose, GitHub Actions (lint, typecheck, unit, integration, e2e, axe, secret-bundle scan).
- **Deploy targets:** (a) local Compose (default, $0); (b) a single small VM running the same Compose behind Caddy (TLS), nightly `mysqldump` + restic backups and a tested restore script.

Topology:
```
Browser -> Next.js "web" (UI, /api route handlers, Better Auth, Drizzle -> MySQL [only writer])
web -> Redis/BullMQ -> worker-node (GitHub sync, mentor calls, report jobs)
                    -> worker-py   (stats, simulations, trace analysis)
web -> api-py (FastAPI, HMAC-signed internal calls, sync compute < 5 s)
worker-py -> web POST /api/internal/jobs/:id/result (HMAC) -> web writes DB
atlas-lab CLI (laptop or GPU box) -> web /api/runner/* (scoped, hashed, expiring tokens)
```

## 6. Feature requirements

### 6.1 Learning core
- Diagnostic (timed; code tests, MCQ, short answers by rubric) -> skill map + recommended mode (Accelerated 16 weeks / Research-Intensive 24 weeks) + calendar for the chosen hours (20/30/40/50 per week). Planning estimates: RI content is ~960 h and ACC content ~800 h, so at 20 h/week RI takes ~48 weeks; at 30 h ~32; at 40 h 24; at 50 h ~19. After week 2, re-estimate from actual time per passed gate.
- **Gates unlock progress; hours never do.** Each gate has objective tests and/or a rubric plus required evidence (commit SHA, report, recording). Advanced weeks (18+) stay locked until the week-12 and week-15 exams pass.
- FSRS spaced repetition (ts-fsrs): daily retrieval quiz from earlier weeks; cumulative tests at weeks 6/12/18/24; target retention 0.9.
- Remediation: a failed gate creates a remediation plan and locks only dependent skills.
- AI rule: in foundation labs (weeks 1-12 RI), the mentor may ask questions and point to docs but not output code blocks longer than 3 lines (server-side filter).
- Exercises: Python runs in-browser with Pyodide; C/Go/C++/CUDA run through `atlas-lab` on the learner's machine in Docker (`--network none`, CPU/memory limits). The hosted server never executes user code.

### 6.2 Four separate meters (never merged into one number; each shows its formula and evidence)
Learning progress (gates passed, retention) · Engineering proficiency (tests, CI, exams, review findings) · Research quality (reproducibility checklist, baselines, CIs, confounders, reviewer rubric) · Hiring readiness (evidence checklist only, with the text "This is a checklist of evidence, not a prediction of interviews or offers"). No "recruiter score" anywhere.

### 6.3 Research engine
- Source verification jobs: arXiv export API (`export.arxiv.org/api/query?id_list=`), GitHub REST (`/repos/{o}/{r}`, `/repos/{o}/{r}/issues/{n}`), HTTP GET + title (a captcha or "access denied" page counts as `broken`/`partial`, never `verified`), price pages (always shown as "estimate, read on DATE"), public job-board APIs (quoted verbatim).
- Dossiers with these 20 fields: problem, why it matters, existing approaches, papers, OSS implementations, evidence it is unresolved, prerequisites, hardware, feasibility 1-5, difficulty 1-5, hypothesis, method, baselines, metrics, confounders, reproducibility, contribution path, publication venues, risks, next experiment.
- Five classifications with enforced rules. **Documented open problem** needs a primary source saying it is unresolved, dated within 12 months (or an override note). **Engineering optimization opportunity** means the technique is known and measurable improvement is still possible. **Unverified hypothesis** needs a stored novelty-check log (arXiv search + GitHub issue search in the 3 most relevant repos + docs). The UI never says "novel"; it says "no prior work found in these searches". **Already solved** means published and in mainstream systems, so it's a reproduction target. **Beginner-friendly contribution** means the platform's own estimator scores the issue at most 2/5, a maintainer was active within 90 days, and no competing PR exists. A `good first issue` label alone never qualifies.
- Issue difficulty estimator (1-5 + reasons): modules touched, RFC/design discussion, maintainers involved, test infra needed (GPU/multi-node), age vs activity, existing PR attempts.
- Experiment methodology the lab enforces: pre-registration (hypothesis, primary metric, baseline, stopping rule, timestamp); automatic env capture; warm-up runs excluded; at least 5 repetitions by default; median, p95/p99 and bootstrap CIs; one variable changed at a time; confounder checklist; failed runs kept and shown. The report generator refuses "X% faster" without a same-environment baseline.

### 6.4 Local runner `atlas-lab` (Python + Typer)
`atlas-lab login --token`, `atlas-lab run <exercise|experiment> [--dry-run] [--repeat N] [--gpu-rate USD_PER_HOUR] [--max-hours H]`, `atlas-lab upload results.json`, `atlas-lab notebook export|import`. It captures CPU/GPU model, driver, CUDA, libraries, git SHA, container digest and `nvidia-smi topo -m` when available, and samples GPU util/memory/power via `nvidia-smi` when present. Before a GPU run it prints the estimated cost (hours x rate), writes an auto-shutdown script and wraps the job in a timeout. It exports and imports Jupyter notebooks (nbformat) using the same upload schema.

### 6.5 GitHub workspace
Target repos, seeded, with licence and activity re-fetched: vllm-project/vllm, sgl-project/sglang, ray-project/ray, pytorch/pytorch, kubernetes/kubernetes, triton-lang/triton, apache/arrow, apache/datafusion, pingcap/tidb, etcd-io/etcd, etcd-io/raft, LMCache/LMCache, llm-d/llm-d, kubernetes-sigs/gateway-api-inference-extension, vllm-project/guidellm, microsoft/vidur. Hide archived repos (huggingface/text-generation-inference was archived on 2026-03-21). Label source-available repos (cockroachdb/cockroach uses the CockroachDB Software License) as "not open source". Each issue gets a checklist: CONTRIBUTING and code of conduct, CLA/DCO, check for existing PRs, reproduce, failing test, implement, project lint/tests, and a PR description template **for copying**. The tracker covers PR state, reviews, time to first review and merges. Merged PRs become portfolio evidence after API verification.

### 6.6 AI mentor (optional; app fully usable with it off)
Provider adapter interface (at least one real provider + "none"; provider/model configurable; keys server-side, encrypted, write-only). Modes: Socratic tutor, code reviewer, benchmark-method reviewer, paper explainer, debugging guide, mock interviewer, system-design critic. It asks guiding questions first, then offers a hint ladder (concept -> location -> pseudo-code). Full solutions to graded exercises stay withheld until the gate passes, and the server enforces this from attempt state, not from the prompt alone. Every message is tagged "AI-generated". Research claims carry confidence computed from citations: high = at least 2 stored primary sources or the learner's own reproduced run, medium = 1, low = none, shown as "unverified suggestion". The mentor writes weakness observations that the learner can view and delete. Fetched content (issues, READMEs, papers) is passed as quoted data, never as instructions. The mentor has no tools that write anywhere. Cost controls: a price table with source URL and verified_at, a pre-call estimate, per-request output cap, and daily/monthly USD caps that refuse the call before it reaches the provider. Default to the cheapest configured model.

### 6.7 Career visibility
Portfolio builder that accepts only verified artifacts. Public pages per item. Quality checks on linked repos: README with run steps, LICENSE, CI passing, tests, reproducible benchmark script. Writing helpers (LinkedIn project summary, resume bullets, blog draft) where each sentence links to evidence, and sentences without evidence are rejected. Copy buttons only, never post buttons. Also: a conference/community list (MLSys, OSDI, SOSP, NSDI, GPU MODE, official project channels) with verified_at dates, presentation-practice recording that stays local by default, and an interview simulator (coding with hidden tests, system design with rubric, "defend your project" with rubric).

### 6.8 Cost controls and budgets (show in Settings and in README)

VAT, or Railway Hobby at $5 minimum usage) running Compose; about $10 of GPU (e.g. Runpod RTX 3090 about $0.50/h, RTX A5000 about $0.27/h); mentor capped at about $5 (e.g. Claude Haiku 5.5 at $0.10 in / $0.50 out per million tokens for prompts up to 100k tokens).

- Guardrails to implement or document: provider spend caps first (Modal workspace budget, Vercel hard pause, since new Vercel teams default to a $200 on-demand budget), GPU timeouts and auto-shutdown, deleting volumes after runs, public repos for free GitHub Actions minutes, hard AI caps. The platform never launches paid resources itself in v1.
